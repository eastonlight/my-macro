# oh-my-macro

Windows 데스크톱용 **StarCraft 1 매크로 도우미**입니다. Rust + eframe/egui로 만들었고 AutoHotkey가 필요 없습니다.

**줄짓기 건설**, **화면 내 스파이어 감지 → 좌클릭 → A**, 그리고 **F4 저장 화면의 빈자리에 크립 콜로니 건설**을 지원합니다. 각 기능은 별도 단축키를 쓰며 동시에 실행되지 않습니다.

| 단축키 | 동작 |
| --- | --- |
| `~` (Tilde, 기본·변경 가능) | 아래 **드론 줄짓기 매크로** 실행 — 드론 **2~12기**를 자동 인식해 배치 순서대로 건설. **드론 1기**면 커서 위치에 한 채만 |
| `Tab` (기본, 변경 가능) | 스파이어 감지 동작 — 누르면 **바로** 화면을 한 번 탐색해 감지된 각 스파이어를 클릭하고, 선택 패널 확인 후 `A` |
| `F6` (기본, 변경 가능) | **F4 저장 화면 빈자리 건설** — 게임의 F4 화면으로 이동해 빈자리를 검증하며 크립 콜로니를 지음 |
| `F8` (고정) | 응급 정지 — 즉시 취소 + 무장 해제 |

단축키는 GUI에서 F1~F12·Tilde·Tab 중에서 고를 수 있습니다(**`F4`와 `F8`은 제외** — F4는 게임의 저장 화면 키이고 이 앱이 직접 누르는 키이기도 하며, F8은 응급 정지). **기본값은 트리거 `~`, 스파이어 동작 `Tab`, 빈자리 건설 `F6`**이며, 예전 파일에 `F6`+`F7` 쌍이 저장돼 있으면 새 기본값(`~`+`Tab`)으로 바뀝니다(다른 키를 쓰던 설정은 그대로 유지). 세 번째 키가 없던 파일은 `F6`(이미 쓰이면 `F7`, 그다음 `F9`)를 씁니다.

> **게임이 쓰는 F키:** 스타크래프트 1은 **F2·F3·F4**(지정 화면)와 **F5**를 직접 사용하고, **F10**은 메뉴입니다. 그래서 세 번째 기능의 기본값은 `F5`가 아니라 **`F6`**이고, 대체 키도 `F7`·`F9`로 잡았습니다. `F5`를 포함한 어떤 키든 GUI에서 직접 고를 수는 있지만, 게임 키와 겹치면 그 키를 게임이 못 쓰게 되므로(핫키를 앱이 가져갑니다) 기본값으로는 쓰지 않습니다.

- 지을 건물은 GUI의 **체크박스 하나**로 고릅니다: 체크 해제 = **크립 콜로니**(`B`→`C`), 체크 = **둥지탑/Spire**(`V`→`S`). **두 건물 모두 2타일(144 px) 간격**으로 배치합니다.
- 세 축은 서로 독립입니다: **배치 순서**(좌→우 / 양끝→가운데 / 6x2 두 줄), **건물 종류**(크립 콜로니 / 둥지탑), **타이밍**(텍스트로 입력하는 press/gap 값).
- 타이밍은 **숫자를 직접 입력**합니다(슬라이더 없음). 범위(1–2000 ms)를 벗어나거나 숫자가 아니면 적용되지 않고 그 자리에서 표시만 됩니다.
- **미리보기 확인 실패 시에도 강행** 체크박스가 기본으로 켜져 있습니다: 초록 미리보기를 **짧게(약 200 ms)** 확인하고, 그래도 보이지 않으면 클릭하고 계속 진행하며, 그런 명령은 결과에 "미확인(강행)"으로 표시됩니다. 끄면 예전처럼 클릭하지 않고 중단합니다.

**마우스 좌표는 설정에 저장하지 않습니다.** 줄짓기는 실행 시 커서를 시작점으로 사용하고, 스파이어 동작은 매 실행마다 새로 감지한 위치로 커서를 이동합니다.
**이 매크로는 게임 화면을 캡처해 선택 개수와 미리보기를 읽으므로, 지원하는 해상도/HUD에서만 동작합니다(아래 참고).**

---

## 요구 사항

- Windows 10/11 (x64)
- StarCraft 1 (1.16.1 또는 리마스터)
- 빌드할 경우 Rust 1.95 이상

## 실행 파일 (Windows)

생성된 Windows x64 릴리스 실행 파일은 **`dist/oh-my-macro.exe`**입니다.
Windows 폴더로 복사한 뒤 실행하세요. Rust 설치나 별도 MinGW 런타임 DLL은 필요하지 않습니다.
코드 서명은 하지 않은 개발용 빌드이며, 실제 GUI·게임 동작은 아직 검증하지 않았습니다.

## 빌드 및 실행 (Windows)

```powershell
cargo run --release
```

릴리스 실행 파일만 만들려면:

```powershell
cargo build --release
# 결과: target\release\oh-my-macro.exe
```

- 설정 파일은 처음 저장할 때 `%APPDATA%\oh-my-macro\config.toml`에 만들어집니다.
- 콘솔 창이 함께 뜹니다. 오류/진단 메시지를 stderr로 보여주기 위해 일부러 남겨두었습니다.
  콘솔이 싫으면 `src/main.rs` 맨 위에 `#![cfg_attr(windows, windows_subsystem = "windows")]`를 추가하세요(대신 오류 메시지가 보이지 않습니다).
- 다른 호스트에서 컴파일만 확인하려면:

  ```bash
  cargo check --target x86_64-pc-windows-gnu
  ```

  (실제 `.exe`를 링크하려면 mingw-w64 링커가 필요합니다.)

## 스파이어 감지 → 좌클릭 → A (기본 Tab, 실험적)

1. 게임에서 스파이어가 보이는 위치에 마우스를 두고, 게임 창을 전면에 둔 채 앱을 무장한 다음 동작 단축키(기본 `Tab`)를 누릅니다.
2. 앱이 화면을 **한 번** 탐색해 스파이어를 찾고, 각 위치로 커서를 옮겨 **좌클릭 → 선택 패널 확인 → `A` 한 번**을 보냅니다.
3. 결과 창에 감지 개수·위치·탐색/감지 시간·건너뜀 수가 표시됩니다. **확인이 안 된 위치에는 `A`를 보내지 않습니다.**
4. F8은 두 기능 모두를 취소·해제합니다. 실행 중 카메라를 이동하거나 마우스·키를 함께 조작하지 마세요. 채팅 상태는 감지하지 못합니다.

**주의:** 건물 종류만 확인하며, 그 스파이어가 **내 것인지, 지금 업그레이드가 가능한지**는 확인하지 않습니다. 다른 플레이어의 스파이어나 업그레이드 불가 상태에서도 클릭과 `A`가 나갈 수 있습니다.

- 로컬 CPU의 작은 이미지 패턴 비교(그레이스케일 정규화 상관 + 에지 일치도)이며 네트워크/AI 호출은 없습니다. **전체 화면 탐색은 실행당 한 번**입니다. 클릭 후에는 104×140 선택 패널만 검사합니다.
- **현재 Win32 캡처는 패널 확인 때도 전체 클라이언트를 렌더링한 뒤 잘라내므로, 물리적 화면 캡처가 실행 전체에서 딱 한 번인 것은 아닙니다.** 대상마다 캡처 비용이 더해집니다.
- 사용자 제공 실제 화면 2장으로 확인한 결과: 스파이어 4개 장면 **4/4 탐지**, 밀집 장면(같은 종류 15개 + 상단 잘림 2 + HUD 가림 1 + 둥지탑 1)에서 **완전히 보이는 15개 모두 탐지, 오탐 0**. 이전 버전은 같은 밀집 장면에서 10개만 찾았습니다.
- Linux release에서 탐지 시간은 4개 장면 **54–61ms**, 15개 장면 **63–67ms**였습니다(6회 측정, PNG 디코딩·Win32 캡처·게임 입력 시간 제외).
- 탐지 대상은 **완전히 보이는 크라운**입니다. 화면 위/아래로 잘렸거나 HUD에 가려진 건물은 의도적으로 제외하며, 그런 건물은 결과에 나타나지 않습니다. 탐색 클릭 중심 범위는 대략 x=24..1895, y=24..769(하단은 구간별 HUD 경계)입니다.
- 두 장면 모두 **같은 맵·카메라·팀 색상**입니다. 다른 맵/줌/팀 색상/스킨/애니메이션/부분 가림에서의 정확도와, 실제 게임에서의 클릭→`A` 결과는 아직 검증하지 않았습니다. 다른 건물(크립 콜로니·둥지탑·그레이터 스파이어)·드론 패널을 스파이어로 받아들이지 않는 회귀 테스트는 포함합니다.
- 트리거가 `Tab`이면 동작 키 기본값은 `F9`가 됩니다. 명시적인 중복 키나 F8 지정은 거부합니다.

## 드론 줄짓기 매크로 (트리거 단축키 하나, 2~12기, 실험적)

**트리거 단축키 하나**가 매크로를 실행합니다(기본 `~`). 매크로는 먼저 게임 화면을 캡처해 **선택된 드론 수(2~12기)**를 픽셀로 인식한 뒤, 커서 위치부터 **오른쪽으로 건물 간격만큼 떨어진 한 줄**을 짓습니다. 드론이 1기면 그룹 9를 건드리지 않고 커서 위치에 한 채만 짓습니다.

### 건물 선택 (체크박스 하나)

줄짓기 카드의 체크박스가 지을 건물을 고릅니다. 줄짓기 트리거 하나가 이 설정을 따릅니다. 별도 스파이어 감지 단축키는 건설을 하지 않습니다.

| 체크박스 | 건물 | 입력 순서 | 발자국 | 1920x1080 간격 |
| --- | --- | --- | --- | --- |
| 해제 (기본) | 크립 콜로니 (Creep Colony) | `B` → `C` → 좌클릭 | 2x2 타일 | **144 px** (실기 검증됨) |
| 체크 | 둥지탑 (Spire) | `V` → `S` → 좌클릭 | 2x2 타일 | **144 px** (둥지탑은 아직 실기 검증 안 됨) |

- 간격은 **줄의 중심 간 거리**입니다: 커서가 첫 발자국이고, 다음 발자국은 144px 오른쪽입니다.
- 144px는 "1920x1080에서 타일 1개 = 72px"에서 나온 2타일 값입니다. **둥지탑 쪽은 아직 실기에서 직접 재어보지 않았습니다.** 간격이 실제와 다르면 초록 미리보기 검증이 실패합니다: 강행 모드가 켜져 있으면(기본) 그래도 클릭하고 계속하며 그 명령을 "미확인"으로 보고하고, 꺼져 있으면 클릭하지 않고 중단합니다.
- 미리보기 인식은 건물 발자국 크기에 맞춰 스케일됩니다(둘 다 144px).

### 배치 순서 (세 가지)

줄의 **범위(span)는 순서와 무관하게 항상 같습니다.** 커서가 있는 발자국이 줄의 **맨 왼쪽** 발자국이고, 목표는 오른쪽으로 건물 간격만큼 떨어져 있으며, 드론 수만큼의 발자국을 모두 사용합니다. 설정으로 바뀌는 것은 **그 발자국을 짓는 순서**뿐입니다.

| 모드 | 설정 값 | 순서(발자국 번호, 0 = 맨 왼쪽) |
| --- | --- | --- |
| 왼쪽→오른쪽 (기본) | `left_to_right` | `0, 1, 2, …` — 커서부터 오른쪽으로 차례대로 |
| 양끝→가운데 | `ends_inward` | `0, 마지막, 1, 마지막-1, …` — 남은 양끝을 번갈아 가운데로 수렴 |
| 6x2 두 줄 | `grid_6x2` | 1~6번은 아래 줄, 7~12번은 **한 줄 위**에 6열로 배치(144px 간격, 위 줄은 144px 높이 차이) |

**한 줄 모드(`left_to_right`, `ends_inward`)는 선택이 11~12기여도 10기까지만 사용합니다.** 시작하기 전에 남는 초상화를 Shift-클릭으로 해제해 10기로 줄인 뒤 줄을 짓습니다(선택이 실제로 바뀝니다). 12기를 전부 쓰려면 **6x2** 모드를 고르세요. 이 동작은 두 줄 모두 6열(864px)이면 들어가기 때문에 가능합니다.

**드론 5기 예시(크립 콜로니)** — 목표 발자국은 두 모드 모두 커서 기준 오프셋 `0, 144, 288, 432, 576`으로 같고, 짓는 순서만 다릅니다.

- `left_to_right`: 0 → 144 → 288 → 432 → 576
- `ends_inward`: 0 → 576 → 144 → 432 → 288

둥지탑도 간격이 같으므로 같은 오프셋을 그대로 씁니다. 6x2 모드라면 12기의 목표는 `(0,0) … (720,0)` 아래 줄 6채와 `(0,-144) … (720,-144)` 위 줄 6채가 됩니다.

드론 수별 `ends_inward` 순서: 2기 `0,1` / 3기 `0,2,1` / 4기 `0,3,1,2` / 5기 `0,4,1,3,2` / 6기 `0,5,1,4,2,3` … 12기 `0,11,1,10,2,9,3,8,4,7,5,6`.

- 순서와 건물 종류는 **설정 파일에 저장됩니다**(`colony_row_mode`, `build_target`). GUI의 줄짓기 카드 안에서 고를 수 있고, 무장 중에는 다른 설정과 같이 잠깁니다.
- 공간 부족·HUD/가장자리 침범 사전 검사는 두 모드가 **완전히 동일**합니다(같은 범위를 검사하므로).
- 드론 1기일 때는 순서가 의미가 없으므로 두 모드가 같게 동작합니다.

- **지원 프로필은 딱 하나입니다.** StarCraft 1 리마스터, 클라이언트 **1920x1080**, 기본 HUD/스킨, 그리고 그 창이 **주 모니터 좌상단 (0,0)에 1920x1080 크기로** 놓여 있어야 합니다.
  다른 해상도·HUD·스킨·창 위치에서는 **아무 입력도 보내지 않고 중단**하며 창에 이유를 표시합니다(추측 확대/축소 없음). 창을 옮기거나 크기를 바꾸거나 포커스를 잃으면 실행 중에도 즉시 중단합니다.
- **임시 컨트롤 그룹 9번을 사용합니다.** 기존에 9번 그룹에 저장해 둔 내용은 **덮어쓰여집니다**(실행마다 재사용). 다른 그룹 번호는 건드리지 않습니다.
- 아래 프로토콜을 실제 게임에서 확인했습니다(크립 콜로니 기준): 드론 선택 → `Ctrl+9`로 임시 그룹 저장 → 마지막 초상화 클릭 → 건물 입력 순서(`B`,`C` 또는 `V`,`S`) → 초록 미리보기 확인 후 클릭 → `9`로 그룹 소환 → 아직 이동 중이면 마지막 초상화를 `Shift+클릭`해 제외 → `Ctrl+9`로 남은 드론 재저장. 마지막 한 기는 **1기 정보 패널**로 표시되므로 바로 입력 순서를 누릅니다.
- **드론 1기**만 선택한 경우에는 그룹 9를 건드리지 않고 커서 위치에 한 채만 짓습니다.

안전 규칙:

- 공간 부족·화면 가장자리·HUD 침범이면 **그룹 저장이나 입력 주입 전에** 먼저 거부합니다(카메라 스크롤 방지).
- **가로 여백(수정됨):** 예전에는 오른쪽에 `여백 48 + 건물 반폭 + 32`(콜로니 152px, 둥지탑 224px)를 남겨 두어 **화면에 들어가는데도 11~12채 줄이 거부**됐습니다. 이제 클릭 지점만 보정된 경계(24px)로 검사하므로 같은 커서에서 더 멀리까지 지을 수 있습니다.
  - 두 건물 공통(144px 간격): 한 줄 12채는 커서 x ≤ **311**, 11채 x ≤ **455**, 10채 x ≤ **599**. 화면 폭 1920에서 12채는 1584px가 필요하므로 커서가 그보다 오른쪽이면 물리적으로 불가능합니다. (6x2 모드는 6열만 쓰므로 이 제한이 훨씬 완화됩니다.)
  - 거부될 때는 상태줄에 **몇 채까지 들어가는지**(예: `this cursor position 10 of 12 buildings fit`)가 함께 표시됩니다.
  - **낮게 지을수록 가로 폭이 줄어듭니다.** 커맨드 카드가 오른쪽 아래를 차지하므로, 커서가 y≥710이면 x<1340까지만, 중앙 하단(y≈769)에서는 x<1260까지만 줄이 들어갑니다. 줄의 뒤쪽 지점이 경계를 넘으면 입력 전에 줄 전체를 거부합니다.
- **커서 위치 경계(보정됨):** 이제 건물 크기만큼 위·아래를 잘라내지 않고, **클릭 지점 자체**를 실제 HUD 윤곽(`src/play_area.rs`)과 화면 가장자리(24px)에 대조합니다. 상단은 y=24까지, 중앙 하단은 y≈769까지 허용됩니다(미니맵 왼쪽·커맨드 카드 오른쪽은 더 위에서 막힘). 줄의 **뒤쪽 발자국이 HUD에 닿으면 입력 전에 줄 전체를 거부**합니다.
  실측 근거: 이 화면에서 미니맵 콘솔 윤곽 ≈690–717, 중앙 콘솔 ≈782–800, 커맨드 카드 ≈715–740 (x=400 HUD 곡선 지점 기준 여유 20px 이상). 남은 위험: 실제 HUD가 화면 밖으로 잘렸거나 창 크기가 다르면 보정이 어긋날 수 있으므로, 이런 환경은 지원 프로필 검사에서 거부합니다.
- **미리보기 검증**: 각 목표 위치에서 초록색(건설 가능) 미리보기를 캡처로 확인한 뒤에만 클릭합니다(강행 모드가 꺼져 있을 때의 기본 동작). 빨간색(불가)·모호·미리보기 없음이면 **클릭하지 않고 중단**합니다.
- **강행 모드(기본 켜짐)**: 배치 미리보기를 **최대 약 200 ms만** 확인하고, 초록 미리보기를 확인하지 못하면 **그래도 클릭하고 다음 드론으로 넘어갑니다**(사용자 요청). 강행 모드에서는 빨간 미리보기에도 추가 대기 없이 클릭합니다. 미리보기 인식이 틀리면 이동 등 의도하지 않은 게임 입력이 될 수 있으며, 실제 건설 성공을 보장하지 않습니다. 클릭 후에도 배치 모드가 **계속 보이면** `Esc`를 한 번 눌러 정리하고 계속합니다(모호하게 감지된 경우에는 `Esc`를 누르지 않습니다). 이런 명령은 결과 줄에 `미확인(강행)`으로 표시됩니다.
- 선택이 드론이 아니거나, 여러 유닛이 섞였거나, 12기를 넘거나, 캡처가 검거나, 툴팁이 HUD를 가리면 **실패 폐쇄(fail-closed)** 합니다.
- F8/무장 해제/포커스 변경 시 즉시 취소하고, 이 앱이 눌렀던 키·수정키·마우스 버튼만 해제합니다.
- 표시되는 수치는 **보낸 명령 수**이며, 실제로 건물이 완성됐다는 보장이 아닙니다.

한계(정직한 기록):

- **지형·경로 탐색을 보장하지 않습니다.** 목표 지점이 막혔거나 계곡 등이면 건물이 지어지지 않습니다(강행 모드에서는 클릭만 하고 계속 진행합니다).
- 게임이 그룹 9 소환 시 카메라를 이동시키면 화면 기준 목표가 어긋날 수 있습니다. 강행 모드에서는 그런 경우에도 클릭하므로, **강행 모드는 미리보기 인식이 정상일 때만 켜 두는 것을 권장합니다.**
- 마우스를 선택 패널 위에 둔 채 단축키를 누르면 툴팁이 초상화를 가릴 수 있습니다. 이 경우 인식에 실패하고 아무 입력도 보내지 않습니다. **지을 위치(필드)에 마우스를 두고 트리거 단축키를 누르세요.**
- **둥지탑 간격(144px)과 둥지탑 입력 순서(`V`→`S`)는 실기 검증되지 않았습니다.** 콜로니에서 재어 둔 2타일 값을 그대로 적용한 것이라, 실제로 다르면 미리보기 검증이 실패하고 강행 모드에서는 클릭만 하고 넘어갑니다.
- 6~12기는 실제 캡처 대신 **합성 이미지 테스트**로 검증했습니다(아래 "검증 상태" 참고).

## F4 저장 화면 빈자리 건설 (기본 `F6`, 실험적)

게임의 **F4(저장 화면)** 에 크립과 여유 공간이 보이는 위치를 미리 저장해 두고 사용합니다.

1. 게임에서 여유 공간이 보이는 위치에 **F4 저장 화면**을 지정해 둡니다(게임 쪽 지정, 예: `Ctrl+F4`).
2. 드론 **2~12기**를 선택합니다(줄짓기와 같은 방식으로 HUD에서 개수를 읽습니다).
3. 앱을 무장한 뒤 실행키(기본 `F6`)를 누릅니다.
4. 앱이 **F4를 눌러 저장 화면으로 이동**하고, 화면을 **한 타일(72px) 간격**으로 **왼쪽 아래에서 오른쪽으로, 그다음 줄은 위로** 훑으면서 후보마다 다음을 확인한 뒤, **모두 통과한 곳에만** 클릭 한 번을 보냅니다.
   - 초록 건설 미리보기가 **새로 나타났는지**(정지 화면의 초록 지형이 아닌지, 사각형 네 사분면에 모두 초록 변화가 있는지)
   - 같은 후보를 **두 번 연속 읽어** 같은 위치에 미리보기가 있는지(카메라·화면이 변하지 않았는지)
   - 건물 발자국 전체가 **보정된 필드 안**이고 이미 지은 건물과 겹치지 않는지
5. 클릭 한 번(명령 1건) 뒤에는 **그 드론이 실제로 변이를 시작했는지 확인한 다음에만 다음 드론**으로 넘어갑니다.
   - 확인은 **선택 패널이 드론이 아니라 변이 중인 콜로니 패널(진행 바)로 바뀌었는지**를 **연속 두 번** 읽고, 그 동안 **주문한 자리의 월드 영역이 같은 카메라 시야인지**를 함께 확인하는 방식입니다.
   - 미리보기가 닫힌 것, 드론이 떠난 것, 선택이 사라진 것, 그룹이 줄어든 것은 **변이 시작 증거가 아닙니다.**
   - 드론당 정해진 대기 시간(30초) 안에 확인되지 않으면 **다음 드론을 건드리지 않고 부분 결과로 중단**합니다.
6. 확인된 곳이 없으면 **클릭하지 않고 중단**합니다.

- **탐색은 추측이 아니라 검증입니다.** 후보 위치는 "빈자리처럼 보이는 곳"일 뿐이고, 실제 클릭은 게임이 그린 초록 미리보기를 확인한 뒤에만 나갑니다. 따라서 크립 밖·자원·유닛·건물 위에는 (그곳이 초록이 아니므로) 클릭이 나가지 않습니다.
- **강행 없음.** 줄짓기의 "미리보기 확인 실패 시에도 강행"과 달리, 미리보기가 확인되지 않은 후보는 건너뜁니다. 확인된 곳이 하나도 없으면 아무것도 짓지 않고 끝납니다.
- **다음 드론은 앞 드론의 변이 시작을 확인한 뒤에만** 건드립니다. 건설 명령을 보낸 직후 다음 드론을 고르면 이동 중인 드론을 다시 쓰게 되므로, 변이 시작이 확인되지 않으면 **그때까지 보낸 명령만 남기고 중단**합니다.
- **막힌 후보는 한 번 더 늦게 검사합니다.** 다른 드론이 지나가느라 잠깐 막힌 후보를 한 번의 실패로 영구히 버리지 않습니다(드론 하나당 두 번 탐색, 후보당 최대 두 번).
- 드론 **12기까지 전부** 사용합니다(줄짓기 한 줄 모드의 10기 상한 없음).
- **그룹 9를 임시로 사용하며 덮어씁니다**(줄짓기와 동일한 규칙).
- 실행 중 카메라가 움직이면(그룹 소환 등) **F4를 다시 눌러 같은 화면을 복원**한 뒤 계속합니다. 복원 후에도 화면이 달라 보이면 좌표가 어긋난 것으로 보고 **중단**합니다.
- **시간은 유한하지만 고정된 벽시계 완료 시간을 보장하지 않습니다.** 탐색은 협조적 예산(실행 전체 후보 384곳, 드론 하나 128곳, 실행 전체 탐색 60초 중 먼저 닿는 쪽)이고, 드론당 변이 대기는 30초이며, 실행 전체는 그 합(최대 약 7분)을 넘지 않도록 확인합니다. 캡처 자체는 도중에 멈출 수 없으므로(협조적 취소) 예산을 조금 넘길 수 있고, F8·포커스 이탈·타임아웃에서는 그때까지의 부분 결과로 끝납니다. 화면 한 장만 탐색하며 **스크롤하지 않습니다.**
- **미리보기가 한 번도 확인되지 않으면 일찍 멈춥니다.** 드론 하나가 후보 24곳을 검사했는데 초록 미리보기가 한 번도 확인되지 않으면, 화면 전체를 계속 훑지 않고 **"초록 미리보기를 확인하지 못했다"는 진단과 함께 중단**합니다(게임/스킨이 달라 감지가 안 맞을 때 이렇게 됩니다). 강행 모드가 있는 줄짓기와 달리 이 기능은 확인 없이 클릭하지 않습니다.
- 실행 중에는 카드에 **검사한 후보 수 · 보낸 명령 수 · 변이 시작 확인 수가 실시간으로** 표시됩니다. 오래 걸리는 탐색이나 변이 대기가 멈춘 것처럼 보이지 않습니다.
- **변이 시작 판정은 실제 캡처 1장** (`tests/fixtures/remastered-1080/not-drone-colony.png`, 변이 중 콜로니 선택 패널)으로 보정한 패널 판정입니다. 실기에서 패널이 정확히 이 모습으로 바뀌는지는 아직 확인하지 못했고, 확실한 증거가 없으면 클릭을 이어가지 않고 중단합니다.
- 게임이 건물을 **타일 격자에 스냅**시키면 미리보기 중심이 커서에서 최대 한 타일(72px)까지 떨어질 수 있습니다. 이 코드는 그 정도를 같은 발자국으로 인정하고, 클릭은 커서 자리(미리보기가 그려진 발자국)로 보냅니다. 기록은 스냅된 중심으로 하므로 간격 계산이 어긋나지 않습니다(스냅 자체를 실기로 확인한 것은 아닙니다).
- 결과에는 **보낸 명령 수 / 확인된 변이 시작 수 / 감지한 드론 수 / 검사한 후보 수**가 표시되고, 어느 것도 **"건설 완료 수"가 아니라는 점**이 함께 표시됩니다. 드론이 이동 중이거나 자원이 부족하면 명령이 실행되지 않을 수 있습니다.
- **`F4`는 앱의 실행키로 지정할 수 없습니다.** 설정 파일에 F4를 쓰면 검증 오류로 거부하며, GUI 콤보에서도 선택할 수 없습니다.
- 이 기능은 줄짓기와 **타이밍(press/gap)만 공유**하며, **강행 모드는 없습니다.** 별도 타이밍 설정은 없습니다.

## 사용법

1. 게임에서 **드론을 2~12기 선택**하고, 건물을 지을 위치(필드)에 **마우스를 이동**해 둡니다. (드론 1기만 선택해도 됩니다.)
2. 카드의 **체크박스로 지을 건물을 고릅니다**(해제 = 크립 콜로니, 체크 = 둥지탑). 필요하면 배치 순서와 타이밍도 함께 조정합니다.
3. 이 앱에서 **"사용 시작(무장)"** 버튼을 누릅니다. (기본값은 **중지 상태**입니다.) 무장 중에는 설정이 잠깁니다.
4. 게임 창을 전면에 둔 상태에서 트리거 단축키(기본 `~`)를 누릅니다.
5. 세 번째 기능은 여유 공간이 보이는 화면을 게임의 F4에 저장해 두고, 드론 2~12기를 선택한 상태에서 실행키(기본 `F6`)를 누릅니다. 드론마다 **미리보기 확인 → 명령 → 변이 시작 확인** 순서로 진행하며, 앞 드론의 변이 시작이 확인되지 않으면 다음 드론으로 가지 않고 부분 결과로 멈춥니다.
6. 그만 쓸 때는 **"중지 (해제)"** 버튼을 누릅니다. `F8`도 즉시 중지시킵니다.

주의할 점:

- 드론 선택과 마우스 위치는 **미리 준비**해야 합니다. 앱이 선택을 대신 만들어주지 않습니다(선택 수만 읽습니다).
- 건물·단축키·타이밍은 **무장 중에는 변경할 수 없습니다.** 먼저 중지한 뒤 바꾸세요.
- **연타/자동 반복은 없습니다.** 실행 중에 다시 눌러도 무시하며, 대기열에 쌓지 않습니다.
- **한 번에 하나만** 실행됩니다. 실행 중에 트리거를 다시 눌러도 무시되며 대기열에 쌓지 않습니다.
- 종료 시 앱이 실제로 누른 뒤 아직 해제하지 못한 키/버튼만 해제를 재시도합니다. 안전 점검에서 거부되면 불필요한 해제 입력도 보내지 않습니다.

## 타이밍 조정

**타이밍은 하나의 press/gap 쌍입니다.** 카드에서 두 값을 **텍스트로 직접 입력**하며(숫자만), 범위를 벗어난 입력은 적용되지 않고 표시만 됩니다.

| 항목 | 기본값 | 범위 | 설명 |
| --- | --- | --- | --- |
| `press_ms` | 20 ms | 1–2000 ms | 키/마우스 버튼을 누른 채 유지하는 시간 |
| `gap_ms` | 20 ms | 1–2000 ms | 한 동작이 끝난 뒤 다음 동작까지의 대기 |

- 건물 종류와 타이밍은 **서로 독립**입니다. 둥지탑도 같은 press/gap을 사용합니다.
- 드론 1기의 키 두 개 + 클릭에 설정된 **입력 대기 합계는 120 ms** (`3 × (20 + 20)`)입니다. 실제 실행 시간에는 캡처·인식·상태 확인 시간이 추가됩니다.
- 여러 기를 지을 때는 드론마다 위 press/gap을 키 입력·클릭에 그대로 쓰고, 여기에 **화면 전환을 기다리는 유한 시간**이 더해집니다(상태가 이미 맞으면 기다리지 않고 바로 진행). **엄격 모드**는 각 전환을 최대 1500 ms까지 기다리고, **강행 모드**는 배치 미리보기 확인을 **최대 약 200 ms**로 제한한 뒤 클릭합니다. 재시도 간격은 gap과 최소 20 ms 중 큰 값입니다.
### 스파이어 동작 속도 (한 곳당)

- 클릭 → A 한 곳당 고정 대기는 **약 77 ms**(커서 이동 12 + 클릭 유지 20 + 배치 후 패널 프레임 20 + `A` 유지 20 + 정리 5)이고, 여기에 선택 패널 확인 캡처 시간이 더해집니다.
- **선택 패널 확인은 이제 화면의 104×140 영역만 읽습니다**(BitBlt). 예전에는 대상마다 1920×1080 전체를 다시 렌더링해 수십 ms가 더 걸렸습니다. 화면 읽기가 실패하거나 검게 나오면 자동으로 예전 방식(전체 렌더 후 잘라내기)으로 되돌아갑니다.
- 그래서 15곳 기준 실행 시간은 대략 **2초대 → 1.2초 안팎**으로 줄었습니다(실기 측정치는 아닙니다).
- 더 빠르게 하려면 `press_ms`(누름 유지)를 낮추면 클릭과 `A` 양쪽에서 함께 줄어듭니다. 너무 낮추면 게임이 입력을 놓쳐 `A`가 건너뛰어질 수 있습니다.
- 게임이 입력을 놓치면 **60–80 ms** 정도로 늘려보세요. 반대로 너무 짧으면(특히 10 ms 이하) 키가 씹힐 수 있습니다.
- 기본값이 바뀌어도 **이미 저장된 설정 파일의 press/gap 값은 그대로** 쓰입니다. 바꾸거나 "초기화" 버튼을 누를 때만 달라집니다.
- 취소 플래그는 대기 중 **5 ms 주기**로 확인합니다. 실제 정지 지연은 Windows 스케줄링과 입력 API 처리 시간에 따라 달라집니다.

- **기본 중지 상태**이며, 무장은 명시적으로만 됩니다.

- 전면 창이 대상이 아니면 **그 이벤트를 보내지 않고 실행을 중단**하며, 이유를 창의 상태 영역에 표시합니다.
- **취소/중단/내부 패닉 시에도 누르고 있던 키와 마우스 버튼을 반드시 해제**합니다.

- 무장 중 F8은 리스너 스레드가 취소 플래그를 직접 설정해서, GUI 갱신을 기다리지 않고 즉시 멈춥니다.
- 창을 닫으면 단축키 해제 + 실행 스레드 조인까지 마친 뒤 종료합니다(스레드 누수 없음).
- **Windows가 아닌 호스트에서는 절대 입력을 주입하지 않습니다.** 비 Windows 실행 파일은 안내 문구를 출력하고 종료 코드 1로 끝납니다(패닉 아님).

## 설정 파일

- 위치: `%APPDATA%\oh-my-macro\config.toml` (`APPDATA`가 없으면 실행 파일 옆 `oh-my-macro.toml`)
- 항목:

  ```toml
  trigger_hotkey = "Tilde"    # "Tilde" | "Tab" | F1..F12 (F4/F8 제외) — 줄짓기 트리거
  spire_action_hotkey = "Tab" # 스파이어 감지 동작, 트리거와 중복 불가
  vacant_colony_hotkey = "F6" # F4 저장 화면 빈자리 건설, 다른 두 키·F4·F8과 중복 불가 (F5는 게임 키라 기본값 아님)
  build_target = "colony"     # "colony" | "spire" (체크박스가 쓰는 값)
  colony_row_mode = "left_to_right"  # "left_to_right" | "ends_inward" | "grid_6x2"
  force_build = true          # 짧게 확인 후에도 미리보기가 없으면 클릭하고 진행
  press_ms = 20               # 1..=2000 (기본값; 저장된 값은 그대로 유지됨)
  gap_ms = 20                 # 1..=2000 (기본값; 저장된 값은 그대로 유지됨)
  target_process = "StarCraft.exe"   # exe 파일명(경로 불가)
  ```

- 이 9개 키 외에는 아무것도 기록하지 않습니다. 예전 파일에 `spire_action_hotkey`가 없으면 줄짓기 키와 충돌하지 않는 기본 키를 씁니다.
- 예전 버전이 저장한 `spire_scan_only` 키는 **호환을 위해 읽기만 하고 무시**합니다(스캔만 모드는 삭제됐습니다). 다른 오타 키는 예전처럼 거부하고 경고를 표시합니다.
- `build_target`, `colony_row_mode`, `force_build`가 **없는 예전 설정 파일**은 그대로 읽히며 각각 기본값 `"colony"`, `"left_to_right"`, `true`로 동작합니다. 알 수 없는 값(예: `"hatchery"`, `"middle_out"`)은 추측하지 않고 거부하고 기본값 + 경고를 표시합니다.
- 예전 파일의 두 단축키(`colony_hotkey`, `spire_hotkey`)는 **하나의 트리거**로 합쳐집니다: `trigger_hotkey`가 있으면 그것을, 없으면 `colony_hotkey`, 그다음 `spire_hotkey` 순으로 읽습니다. 트리거가 F8이면 무장이 거부됩니다.

- **예전 설정 파일 이전(매크로별 타이밍)**: `colony_press_ms`/`colony_gap_ms`와 `spire_press_ms`/`spire_gap_ms`만 있던 파일은 **두 쌍의 값이 서로 같을 때만** 그 값을 공유 타이밍으로 읽어들이고, 다음 저장부터는 새 형식(`press_ms`/`gap_ms`)으로 기록합니다.
- 두 쌍의 값이 **서로 다르면** 하나의 공유 값으로 표현할 수 없으므로, 임의로 한쪽을 고르지 않고 **거부하고 기본값 + 경고를 표시**합니다(오류 메시지에 두 쌍의 값이 모두 표시됩니다). 원하는 값을 `press_ms`/`gap_ms`로 직접 적어주세요.
- 공유 형식과 매크로별 형식을 **섞으면**(예: `press_ms`와 `colony_press_ms`가 함께 존재) 어느 값을 써야 할지 모호하므로 거부합니다. 매크로별 값이 **일부만** 있거나 `press_ms`/`gap_ms` 중 **하나만** 있는 파일, 타이밍 값이 아예 없는 파일도 조용히 무시하지 않고 거부합니다.
- `press_ms`/`gap_ms`만 있던 **예전 공유 형식은 지금 형식과 같은 키라서 그대로** 읽힙니다(이전 작업 불필요).
- 잘못된 값, 범위를 벗어난 값, 오타(알 수 없는 필드)가 있으면 **기본값으로 안전하게 되돌리고 창에 경고를 표시**합니다. 조용히 무시하지 않습니다.
- 세 기능의 단축키가 서로 중복되거나 어느 쪽이든 F8이면 검증 오류로 무장이 거부됩니다. **`F4`는 어느 항목에도 쓸 수 없습니다**(게임의 저장 화면 키를 빼앗지 않기 위해). `vacant_colony_hotkey`가 없는 예전 파일은 `F6`(이미 쓰이면 `F7`, 그다음 `F9`)를 씁니다.

## 지원하지 않는 것

확인하지 못함 (Windows 실기 필요):

- GUI 렌더링과 한글 글꼴 로딩(실제 Windows에서의 표시)
- `RegisterHotKey`로 트리거 키와 F8이 실제로 등록/해제되는지
- **줄짓기 매크로의 라이브 실행 전체**(실제 게임에서의 그룹 9 소환·변이·미리보기·카메라 동작). 픽셀 인식은 실제 캡처로, 상태 기계는 합성 캡처로 검증했습니다.
- **둥지탑 경로의 실기 동작**: `V`→`S` 입력 순서와 144px 간격. 콜로니 보정값을 그대로 쓴 것이라 타일 계산 근거만 있습니다. 엄격 모드는 미리보기 검증 실패 시 중단하지만, 강행 모드는 계속 클릭합니다.
- **체크박스로 고른 건물이 실제 게임에서 기대한 건물을 짓는지** (GUI 렌더링 자체도 미검증)
- **둥지탑 8채 초과 또는 가로 공간 부족 시의 거부 동작**은 합성 어댑터로만 검증했습니다.
- **스파이어 감지 동작(기본 `Tab`)의 실기 동작 전체**: 클릭 자체와 `A` 명령의 게임 내 효과. 탐지는 실제 캡처로 검증했지만, 실게임 클릭→A는 아직 실행하지 않았습니다.
- **F4 빈자리 건설의 실기 동작 전체**: F4 소환으로 화면이 실제로 복원되는지, 초록 미리보기 픽셀이 실제 게임에서 이 검사를 통과하는지, 크립 밖·자원 위에서 정말 초록이 뜨지 않는지, 유닛·건물이 있는 화면에서 후보가 충분히 나오는지, 그리고 실제로 건물이 완성되는지는 **아직 게임에서 실행해 보지 않았습니다.** 지금까지의 검증은 합성 어댑터(가짜 데스크톱)와 순수 로직 테스트뿐입니다. 미리보기 픽셀 판정 자체는 **실제 캡처 2장의 초록 미리보기**로 검증했습니다.
- **F4 변이 시작 판정의 실기 동작**: 이 판정은 **실제 캡처 1장**(`not-drone-colony.png`, 변이 중 콜로니 선택 패널)으로 보정했습니다. 게임이 건설 명령 직후 선택 패널을 정말 이 모습(진행 바가 있는 변이 중 콜로니)으로 바꾸는지, 드론이 이동하는 동안과 변이 시작 직후의 패널이 어떤지, 변이 애니메이션 중에도 이 판정이 계속 맞는지는 **게임에서 확인하지 못했습니다.** 합성 패널 테스트와 실제 캡처 1장만으로는 실기 모프 감지를 입증하지 못합니다. 판정이 서지 않으면 기능은 다음 드론으로 가지 않고 부분 결과로 멈춥니다.
- **어두운 지형에서의 후보 검사**: 예전 구현은 검사 영역이 어두우면(=미탐색 검은 지형, 우주, 그림자) 그 영역을 "빈 화면"으로 보고 **창 전체를 다시 렌더**했습니다. 그래서 어두운 맵에서는 후보마다 느린 재렌더가 붙어 탐색이 오래 걸렸습니다. 이제는 **창이 최소화된 경우에만** 전체 렌더로 넘어가고, 어두운 영역은 정상 픽셀로 받아들입니다. 이 경로는 실기에서 다시 확인해야 합니다.
- **보정된 커서 경계(play_area)의 실기 동작**: 화면 2장에서 픽셀로 측정해 보수적으로 잡았지만, 실제 게임에서 그 지점 클릭이 HUD를 건드리지 않는지는 미검증입니다.
- **`SendInput` 스캔코드가 StarCraft 1에서 실제로 동작하는지** (게임 런타임 검증 필요)
- 6~12기 실제 캡처(합성 레이아웃으로만 검증)
- UIPI/관리자 권한 동작, 멀티 모니터/DPI 환경
- 백그라운드(최소화/가림) 상태에서의 핫키 동작

## 코드 구조

```text
src/
  macros.rs        매크로 정의와 이벤트 순서/타이밍 계획 (순수)
  engine.rs        계획 실행, 취소 처리, held 입력 해제 (순수)
  colony.rs        줄짓기 매크로: 행 계획 + 그룹 9 상태 기계 + 강행 모드 (순수)
  colony_limited.rs 줄짓기 래퍼: 한 줄 모드의 10기 상한(Shift-클릭 해제), 6x2는 상한 없음
  frame.rs         캡처 프레임 타입 + PNG 로더 + 픽셀 분류기 (순수)
  vision.rs        선택 HUD/배치 미리보기 픽셀 인식 + 변이 시작 패널 판정 (순수, 실제 캡처로 보정)
  runner.rs        스레드 감독: 동시 실행 금지, 보고, 조인 (순수)
  config.rs        설정 모델, 검증, TOML 저장/불러오기 (순수)
  hotkey.rs        단축키 모델 + 트랜잭션 등록 프로토콜 (순수)
  input.rs         InputAdapter/DesktopAdapter 트레이트 seam, 수정키 소유 규칙 (순수)
  ui_text.rs       한국어/영어 문자열 (순수)
  font.rs          한글 글꼴 탐색/검사 (순수)
  windows/
    adapter.rs     SendInput 스캔코드 주입, PrintWindow/GDI 캡처, 커서 이동, 안전 점검
    listener.rs    RegisterHotKey 메시지 펌프 스레드 (MOD_NOREPEAT)
    app.rs         eframe/egui 화면
  main.rs          진입점 (Windows가 아니면 안내 후 종료)
  spire_vision.rs  스파이어 크라운 탐지 + 선택 패널 검증 (순수, 실제 캡처 2장으로 보정)
  spire_action.rs  스파이어 동작 상태 기계: 1회 탐색 → 클릭 → 검증 → A (순수)
  vacant_colony.rs F4 저장 화면 빈자리 건설: 아래 왼쪽부터 탐색 + 미리보기 검증 + 변이 시작 확인 + 그룹 9 프로토콜 (순수)
  play_area.rs     1920x1080 HUD 윤곽/가장자리 보정 (순수)
examples/detect.rs      읽기 전용 픽셀 인식 진단 CLI
examples/spire-scan.rs  읽기 전용 스파이어 탐지 진단 CLI (탐지 시간 분포 출력)
tests/macro_plan.rs          공개 API 스모크 테스트
tests/spire_vision_tests.rs  스파이어 탐지/검증 통합 테스트
tests/fixtures/remastered-1080/    실제 1920x1080 캡처에서 자른 보정용 PNG
tests/fixtures/spire-screen-1080/  스파이어 4개 장면 + 템플릿/마스크 (실제 캡처)
tests/fixtures/spire-dense-1080/   스파이어 밀집 장면 + 주석 이미지 (실제 캡처)
```

- `eframe`/`windows-sys`는 `cfg(windows)` 의존성이라, **Linux에서도 순수 테스트가 그대로 실행**됩니다.
- 매크로 실행은 별도 워커 스레드에서 돌고, 안전 점검도 그 스레드에서 매 이벤트마다 수행되므로 GUI 렌더링과 무관하게 동작합니다.
- 트리거 키도 같은 워커 슬롯을 사용하므로 F8/해제/창 닫기가 동일하게 취소·조인합니다(별도 스레드 없음).
